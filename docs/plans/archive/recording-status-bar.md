# 記録・撮影のミニバー（画面下に常駐）

## 目的・背景

移動中の iOS アプリの肝は **GPS 記録** と **写真・動画の撮影** の 2 つだが、いまはどちらも
`TripDetailView` のボトムシート内「RECORD」セクションの中にしか無い。

- 旅行一覧・日詳細を見ている間は、記録中かどうかも、いま何地点・何 km 記録できているかも分からない
- 撮影したくなったら「一覧 → 旅行 → シートを開く → RECORD まで送る → 撮影」と 4〜5 手かかる
- 記録の停止し忘れ・開始し忘れに気づく場所が無い（一覧の「記録中」タグだけ）

音楽アプリのミニプレイヤーのように、**画面下に記録の状況と操作（撮影 / 記録の開始・停止）を常駐させる**。
どの画面からでも 1 タップで撮影でき、記録中であることが常に目に入る状態にする。

## 対応方針

### 置き場所

`ContentView` の `NavigationStack` の**外側**（`ZStack` の最前面）に 1 つだけ置く。
これで一覧・旅行画面・日詳細のどこへ遷移してもバーは出たままになり、状態も遷移で失われない。

- カメラの `fullScreenCover` も**バーと同じ階層に 1 つだけ**持つ
  （`TripDetailView` にもある現状のままバーにも足すと、同じ `fullScreenCover` が二重になり片方が出なくなる）
- シート（旅行作成・共有取り込み・メディアビューア）が出ている間はバーはその下に隠れる。
  ミニプレイヤーと同じ挙動なので許容する

### 表示条件

| 状況 | 表示 | バーの中身 |
| --- | --- | --- |
| 記録中 | **全画面で常時** | ● 記録中 / 旅行タイトル / 経過・地点数・距離 / 撮影 / 停止 |
| 記録していない・進行中の旅行がある（`startedAt` あり `endedAt` なし） | 全画面で常時 | 旅行タイトル / 「記録していません」/ 撮影 / 記録を開始 |
| 記録していない・旅行画面か日詳細を開いている（未終了の旅行） | その画面の間だけ | 開いている旅行が対象。上と同じ |
| 上のどれでもない（進行中の旅行が無く、一覧に居る） | 非表示 | — |

対象の旅行（撮影・開始の宛先）は **記録中ならその旅行、そうでなければ「開いている旅行」→「進行中の旅行」** の順で決める。
「進行中の旅行」が複数あることは運用上ほぼ無いが、複数なら `startedAt` が新しい方を採る。

> 別案として「記録中だけ出す」（＝完全にミニプレイヤー準拠）もあるが、
> **記録の開始し忘れ**こそ移動中に一番困るので、進行中の旅行がある間は出す方を採る。

### バーの中身と操作

```
┌──────────────────────────────────────────────┐
│ ●  シアトル → シカゴ            [ 📷 ] [ ⏹ ] │
│    記録中 2:41 · 318 地点 · 142.6 km          │
└──────────────────────────────────────────────┘
```

- 左（テキスト領域）をタップ → その旅行の画面へ遷移（`ContentView` の `path` を差し替える）
- 📷 撮影 → `CameraPicker` を全画面で出し、撮ったものを対象の旅行へ取り込む（`MediaImporter`）
  - カメラが無い環境（シミュレータ）では `CameraPicker.isAvailable` が false なので `PhotosPicker` に差し替える
    （現状のツールバーと同じ動線をバー側にも用意し、シミュレータでも確認できるようにする）
- ⏹ / ⏺ 記録の停止・開始（停止時は既存どおり `sync.syncNow()` を呼ぶ）
- 取り込み中（`importer.isImporting`）は 2 行目を「取り込み中…」+ `ProgressView` に差し替える
- 位置情報が拒否・エラーのときは 2 行目をエラー文（`Theme.danger`）にし、タップで設定アプリへ
- 経過時間は `TimelineView(.periodic(from:by:60))` で**分単位**更新（秒更新はバッテリーと再描画がもったいない）
- 見た目は Theme に合わせる（`Theme.panel` + `Theme.line` の角丸、記録中は `Theme.done`、停止は `Theme.danger`）。
  高さは 60pt 程度の定数（`RecordingBar.height`）で持ち、下は home indicator の safe area の上に浮かせる

### 重なりの解消

バーは最前面に浮くので、下端まで中身がある画面は**バーの高さぶん下余白を足す**。

- `SheetList`（`RouteSheet.swift`）の `.safeAreaPadding(.bottom, 28)` を「28 + バー高（表示時）」にする
- `ContentView` の一覧の `.padding(.bottom, 24)` も同様に足す
- `TripDetailView` の地図の `bottomCoverRatio`（シートで隠れる比率）は誤差の範囲なので触らない
- バーの表示・非表示は環境値（例 `\.recordingBarInset`）で各画面に配る

### 旅行画面の RECORD セクションの扱い

バーと同じ操作が 2 か所に出ることになるので、`TripDetailView` の RECORD セクションは
**バーに無い情報だけ**に絞る。

- バーへ移す: 記録中の地点数・距離、撮影ボタン、記録の開始 / 停止
- セクションに残す: 「画面を閉じても記録は続きます」「停止しても旅行は終了しません」の補足、
  権限エラーと設定アプリへのリンク、「別の旅行を記録中です」の案内
- 「旅行を終了」はバーには置かない（後戻りできない操作なので、確認ダイアログのある詳細側に残す）

### iOS / Web の情報の揃え（CLAUDE.md のルール）

バーが出す情報は **地点数・総距離・記録中かどうか** で、いずれも旅行詳細に既にある項目
（Web 側にも同じ項目がある）。**新しい情報項目は増やさない**ので Web 側の追従は不要。
GPS 記録・撮影という**操作**は iOS 固有として許容されている差分。

## 影響範囲

### 新規

- `ios/TripNote/Views/RecordingBar.swift` … バー本体（見た目・ボタン・高さ定数・環境値）
- `ios/TripNote/Domain/RecordingBarState.swift` … 表示条件と文言を決める純粋ロジック（テスト対象）
- `ios/TripNote/Services/ActiveTripContext.swift` … 「いま開いている旅行」を保持する軽い `@Observable`
  （旅行画面・日詳細が `onAppear` / `onDisappear` で出し入れする）
- `ios/TripNoteTests/RecordingBarStateTests.swift`

### 変更

- `ios/TripNote/TripNoteApp.swift` … `ActiveTripContext` を環境へ追加
- `ios/TripNote/ContentView.swift` … `ZStack` でバーを重ねる / カメラの `fullScreenCover` をここへ集約 /
  バーのタップで `path` を差し替えて対象の旅行へ / 一覧の下余白
- `ios/TripNote/Views/TripDetailView.swift` … `ActiveTripContext` の設定、RECORD セクションの整理、
  カメラの `fullScreenCover` をバー側へ移す
- `ios/TripNote/Views/TripDayDetailView.swift` … `ActiveTripContext` の設定
- `ios/TripNote/Views/RouteSheet.swift` … `SheetList` の下余白にバー高を足す
- 新規ファイルを足すので **`xcodegen generate` を再実行**（忘れるとテストが 0 件実行で成功扱いになる）

### 触らないもの

- `LocationRecorder` の記録ロジック（開始・停止・復帰の挙動は現状のまま。呼び出し口が増えるだけ）
- `MediaImporter` / `CameraPicker`（呼び出し元が変わるだけ）
- Web、Android

## Phase / Step

- **Phase 1: バーの土台と状態表示**
  - `RecordingBarState`（表示条件・文言）と `ActiveTripContext` を作る
  - `ContentView` にバーを重ね、記録中 / 未記録 / エラーの表示までを出す（ボタンはまだ置かない）
  - 各画面の下余白を調整して、既存の一覧・シートの最下部がバーに隠れないようにする
  - テキスト領域のタップで対象の旅行へ遷移
- **Phase 2: バーからの操作**
  - 記録の開始 / 停止をバーに載せる（停止時の同期も含む）
  - 撮影をバーに載せ、カメラの `fullScreenCover` を `ContentView` へ集約
    （カメラ非搭載環境は `PhotosPicker` に差し替え）
  - 取り込み中の表示をバーに出す
- **Phase 3: 旅行画面の整理と仕上げ**
  - `TripDetailView` の RECORD セクションを補足・権限案内だけに絞る
  - 実機で移動しながらの動作確認（記録中に別画面へ移動・撮影・停止）

## テスト方針

- **ユニットテスト**（`RecordingBarStateTests`）
  - 記録中 / 進行中の旅行あり / 旅行画面を開いている / どれでもない、の 4 条件で表示・非表示が決まること
  - 対象の旅行の決まり方（記録中 > 開いている旅行 > 進行中の旅行）
  - 文言（「記録中」「記録していません」、権限拒否時のエラー文）と、地点数・距離の整形
  - CLAUDE.md のとおり **unmanaged なエンティティ**（ModelContainer に入れない）で書く
- **ビルド / 既存テスト**: `xcodegen generate` → `xcodebuild ... build` → `... test`
- **シミュレータでの目視**
  - 一覧 → 旅行 → 日詳細と遷移してもバーが出たままで、各画面の最下部の行が隠れないこと
  - シートを 3 段階に動かしてもバーと重ならないこと
  - カメラ非搭載なので撮影ボタンが `PhotosPicker` になっていること
- **実機での確認**（`./run-ios-device.sh`）
  - 記録開始 → 別画面でバーから撮影 → 撮ったメディアが対象の旅行に入る
  - 画面 OFF → 復帰でバーの地点数・距離が伸びている
  - 位置情報を拒否した状態でバーにエラーが出て、設定アプリへ飛べること

## 対象外（今回はやらない）

- Live Activity / Dynamic Island（ロック画面での記録状況表示）。バーが落ち着いてから別タスクで検討する
- バーからの旅行の作成・終了
- Android / Web の追従
