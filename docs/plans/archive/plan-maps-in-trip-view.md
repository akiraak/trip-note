# 旅行画面のプラン地図(日別ミニ地図 + トップは今後の予定)

## 目的・背景

旅行画面(iOS `TripDetailView`)のプラン一覧は日別のテキスト(タイトル・チェックポイント名の
概要)だけで、位置関係はトップの地図 1 枚に全チェックポイントが混ざって表示される。

1. **プラン一覧の各日にその日の地図**を表示し、日ごとの回り方を見えるようにする
2. **トップの地図は「現在の日時以降」の予定**を表示し、これからどこへ行くかが
   すぐ分かるようにする

## 対応方針(iOS のみ。データモデル・同期・API は変更なし)

### 1. 日別リストの各行にミニ地図

- `TripDayRow`(旅行画面のプラン一覧の行)に、その日の**座標ありチェックポイント**の
  ミニ地図を追加する(高さ 120pt 程度・操作不可 `interactionModes: []`。
  タップは従来通り行全体で日詳細へ遷移)
- ピン + 訪問順のポリライン(チェックポイントの sort_order 順)で表示する
- 座標ありチェックポイントが 1 件も無い日は地図を出さない(従来のテキストのみ)
- パフォーマンス: List の行は遅延生成のため日数分の Map を並べても実用と見込むが、
  スクロールが重い場合は `MKMapSnapshotter` の静的画像 + キャッシュに切り替える
  (プラン時点では SwiftUI `Map` で開始)

### 2. トップの地図は「現在の日時以降」

- トップ地図のチェックポイントピンを **今日以降の日(当日を含む)** の分に絞る
  - 判定は trip_days.date(YYYY-MM-DD、端末ローカル)単位。
    当日内の予定時刻(plannedTime)までは見ない(任意入力のため)
  - **全チェックポイントが過去日の場合は従来通り全件表示にフォールバック**
    (終了した旅行・過去の旅行で地図が空になるのを防ぐ)
- 軌跡(記録済みポリライン)とメディアのサムネイルは従来通り表示する
  (「以降」の対象はプランのピンのみ。記録の見返しは損なわない)
- 絞り込みロジックは `PlanEditor` に純関数として置く(例:
  `upcomingDays(of:from:calendar:)` → 今日以降の日、無ければ全日)。
  unmanaged エンティティでユニットテストする

### 補足(スコープ外)

- Web の旅行詳細の地図は従来通り全件表示(必要になったら別タスク)
- 日詳細(`TripDayDetailView`)の地図は実装済みのまま変更なし

## 影響範囲

- iOS: `TripDetailView.swift`(トップ地図の絞り込み・`TripDayRow` のミニ地図)、
  `PlanEditor.swift`(今日以降の日の抽出ロジック)
- web: 変更なし(サーバデプロイ不要)

## テスト方針

- `PlanEditorTests`: 今日以降の日の抽出(当日を含む / 過去日は除外 /
  全て過去日なら全日フォールバック / tombstone の日は含めない)
- 既存テストの回帰(iOS ユニットテスト)+ シミュレータビルド
- 手動: 日別ミニ地図の表示とスクロール性能、トップ地図が今後の予定だけになること、
  終了済み旅行で地図が空にならないこと
