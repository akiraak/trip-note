# 旅行の出発日を変えたらプランの日付も動かす

## 目的・背景

旅行の出発予定日を編集しても、プラン(trip_days)の日付はそのまま残る
(Web の編集フォームにも「プランの日付は動きません」と明記してある)。
出発が 1 日ずれただけで、日ごとのチェックポイントを手で全部直すことになる。

出発日を変えたら**プランの各日も同じだけずらす**。

## 対応方針

- **ずらす量**: 出発日の**日付部分**の差(時刻だけの変更ではずらさない)
  - 旧出発日あり → 「旧 → 新」の日数差だけ**全プラン日**をずらす(日どうしの間隔は保つ)
  - 旧出発日なし(新しく設定した) → **1 日目が新しい出発日になる**ようにずらす
  - 出発日を消した(nil にした)→ 動かさない
- **チェックポイントの `planned_time` も同じ日数ずらす**(日付だけの `date` と
  絶対時刻の `planned_time` がずれないように。既存の日の挿入・削除と同じ扱い)
- **ずらした行だけ** `updated_at` を進める(変わらない行を触ると LWW で
  もう一方の編集を潰すため。これも既存の `shiftDays` と同じ方針)
- **UI で予告する**: 編集フォームに「プランの日付も N 日ずれます」を出す
  (Web の既存の注記「プランの日付は動きません」は差し替え)
- 記録済み(started_at あり)の旅行でも同じ規則で動かす。プラン日は予定であって
  記録(location_points / media)ではないため、特別扱いしない

## 影響範囲

### iOS

- `Domain/PlanEditor.swift`: 出発日の変更からずらす日数を出す純関数
  (`departureShiftDays`)と、trip の全日をずらす `shiftAllDays` を追加。
  既存の `shiftDays(after:by:)` と共通処理をまとめる
- `Views/TripCreateView.swift`(`TripEditView`): 保存時に適用 + 予告文言

### Web

- `src/lib/plan.ts`: `shiftDaysAfter` を任意の日数に一般化し、
  `updateTrip` で出発日の変更に合わせて全日をずらす
- `src/app/trips/[id]/edit-trip.tsx`: 注記の差し替え(「プランの日付も一緒に動きます」)

## Phase

- **Phase 1**: iOS(純関数 + 適用 + 文言)
- **Phase 2**: Web(lib/plan.ts + 文言)
- **Phase 3**: 検証

## テスト方針

- iOS ユニットテスト(`PlanEditorTests`): `departureShiftDays` の
  旧あり/旧なし/消去/時刻だけ変更/日が無い の各ケース
- Web: `npm run lint` + `npm run build`、dev サーバでブラウザから出発日を変更して
  プラン日とチェックポイントの時刻が一緒に動くこと(戻す操作も)
- iOS はシミュレータで編集 → プランの日付が動くことを目視
