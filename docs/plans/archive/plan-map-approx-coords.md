# プラン地図に概算座標を反映(採用時に保存 + ルート描画)

## 目的・背景

日別ミニ地図が 1 日目にしか出ず、ルートも描かれない。原因は、AI 採用で作る
チェックポイントを方針上「座標未定」で保存しているため、座標を持つのが
1 日目の出発地点(現在地)だけになっていること。

## 方針変更

「AI の座標はチェックポイントに保存しない」→
**「AI の概算座標を表示用に保存し、検索で具体化したら上書きする」**に変更する。
概算(市レベル)でも地図・ルートが描ける価値の方が大きい。精密な位置は
従来通り検索で確定させる。

## 対応方針

### 1. AI 応答に概算座標を含めて採用時に保存

- **行程提案(/api/ai/plan)**: `PLAN_SCHEMA` のチェックポイントに
  latitude / longitude(概算)を追加し、パースで範囲チェック(不正は null)。
  Web の採用(`adoptPlanSuggestion` + ai-plan.tsx)と iOS の採用
  (`PlanEditor.adopt(suggestion)`)で座標を保存する
- **日数・宿泊地候補(/api/ai/trip-outline)**: nights の概算座標(実装済み)を
  採用時に宿泊チェックポイントへ保存する(iOS `PlanEditor.adopt(candidate)`)
- 片方だけの座標は両方 null に落とす。`server-api.md` の記述を方針変更に合わせる

### 2. 日別ミニ地図をルートにする

- 2 日目以降は**前日までの最後の座標(前泊地)を起点**にポリラインを引く
  (起点はグレーの点で表示。ピンは当日の分だけ)
- 当日に座標ありチェックポイントが無い日は従来通り地図なし

### 3. トップ地図に今後のプランのルート線

- 今日以降のチェックポイントを日順・訪問順につなぐ**破線ポリライン**を追加
  (記録済みの軌跡 = 実線と区別する)

## 影響範囲

- web: `lib/ai.ts`(PLAN_SCHEMA・パース・プロンプト)、`lib/plan.ts`(AdoptDay・採用)、
  `ai-plan.tsx`、`docs/specs/server-api.md` → **サーバデプロイあり**
- iOS: `AIRecords.swift`、`PlanEditor.swift`(両方の adopt)、
  `TripDetailView.swift`(ミニ地図の起点・トップのルート線)、`TripMapView.swift`(破線)
- DB・同期: 変更なし(既存の latitude/longitude カラムに入れるだけ)
- 既存データ: 過去に採用済みのチェックポイントは座標なしのまま
  (再採用 or 検索で具体化すれば表示される)

## テスト方針

- web: 行程提案パースの座標(正常 / 不正→null)、adoptPlanSuggestion が座標を保存する
- iOS: adopt(行程提案 / 候補)が座標を保存する・無い場合は nil のまま
- 手動: 採用直後に日別ミニ地図がルート付きで出る、トップ地図に今後の破線ルートが出る
