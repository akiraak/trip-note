# 共有ページを地図と写真中心のデザインに変える

## 目的・背景

- 共有ページ（`/share/[token]`）は最初、Web の旅行詳細をそのまま閲覧専用にしたものだった
  （旅行の情報の一覧・プランの日カード・チェックポイントの種別 / 予定時刻 / 座標未設定・メディアの一覧）
- リンクを受け取った人が見たいのは「どこへ行って、何を撮ったか」なので、**地図と写真だけの
  シンプルで見やすいもの**にする
- 4 案（地図が主役 / 写真が主役 / 1日ずつ / 写真マップ）を並べて **C「1日ずつ」を採用**。
  そのうえで「PC は画面いっぱいに使う」「画面の一番上に旅行全体の地図を置く（写真は載せない）」を決めた
- デザイン: https://claude.ai/code/artifact/5959310b-3ed8-4e5c-8341-64159107c7f9

## 対応方針

### 画面

1. **一番上に旅行全体の地図**（電話 300px / PC 420px、全幅）。記録のルート・プランの破線・
   チェックポイントだけを載せ、**写真マーカーは載せない**。旅行名と「期間 · 日数 · 写真の枚数」を
   地図の上に重ねる（今までの共有ページと同じ扱い）
2. **その下に日ごとのカード**。1 枚に「その日の地図・立ち寄り先の 1 行・その日の写真」を入れる。
   PC はカードの中を横並び（地図 480px + 右に立ち寄り先と写真の 6 列グリッド）、電話は縦積み（写真は 3 列）
3. **写真はタップで拡大**。旅行全体を撮影順に前後へ送れる（左右キー・Esc・背景クリックで閉じる）
4. 出さないもの: 旅行の情報の一覧（開始 / 終了 / 出発予定 / 目的地 / 地点数 / 総距離）、
   チェックポイントの種別・予定時刻・到着予想・座標未設定、日のタイトルとメモ、編集の導線

### データ

- `readSharedTrip` を日単位に組み直す。写真・動画は `taken_at` を表示 TZ（America/Los_Angeles）の
  日付にして `trip_days.date` と突き合わせる。**どの日にも当たらない写真は `otherMedia` に回して
  「その他の写真」として出す**（黙って落とさない）
- 記録点は数万件になり得るので日ごとに複製せず、`points` は 1 本だけ返し、日ごとには
  `trackStart` / `trackEnd`（連続した範囲の添字）を持たせる
- さらに**表示用に間引く**（`simplifyTrack`。Douglas-Peucker、許容誤差 15m）。本番の 1 件は
  記録点 99,611 のためページが 12MB あった。共有リンクは他人がスマホで開くので、線の形が
  変わらない範囲で落とす。座標も 5 桁（約 1m）に丸める。**距離や件数の計算には使わないこと**

### 実装上の注意

- 日数ぶんの地図を並べるので、日ごとの地図は **`IntersectionObserver` で遅延マウント**する
  （WebGL コンテキストの上限に当たると古い地図が白く抜ける。旅行詳細の日別地図でも同じ作りだった）
- 道路形状のレグは **SSR で渡したキャッシュ済みの分だけ**を使う。公開経路（Cloudflare Access を
  Bypass する `/share/*`）は GET / HEAD しか通らないので、Server Action は呼べない
- 旅行名を地図に重ねる位置は左だけにする（右上は MapLibre のズームボタンが出る）。
  「旅ログ」の表記はフッタへ
- **共有ページが読み込むものは全部 `/share/` の下に置く**。本番は Cloudflare Access が `/share/*` だけを
  Bypass するので、既定の `/_next/static/` やルート直下から配ると、ログインしていない人には
  資材だけログイン画面が返り素の HTML になる（2026-09-08 に他の PC の Edge で発覚）。
  CSS・JS は `assetPrefix: "/share/_assets"` + rewrite、maplibre のワーカーとアイコンは `public/share/`。
  残る例外は `/favicon.ico`（Next が全ページに入れる）だけで、`/share/icon.png` を宣言してあるため見た目に影響しない

## 影響範囲

- `web/src/lib/share.ts`（日単位の読み出し）、`web/src/app/share/[token]/`（画面一式）
- `web/src/lib/media-stream.ts` と `/share/[token]/media/[id]` は変更なし
- `TripMap` の `mediaBasePath`（共有ページ用に足したもの）は、共有ページが写真マーカーを
  載せなくなったので削除する。`resolveLegs` は残す
- iOS は変更なし。API の口も増減なし

## テスト方針

- vitest: 日ごとの配り分け（表示 TZ での日付）、`otherMedia` に回る条件、記録点の範囲、
  写真と動画の件数、前泊地の引き継ぎ
- `npm run lint` / `npm run build`
- 開発サーバで、電話幅（iframe 390px）と PC 幅の両方の組み、地図の描画、拡大表示の操作を確認する

## 追記: チャットに貼ったときのプレビュー（OGP、2026-09-08）

- `og:title` / `og:description` / `og:image` / `og:url` / `og:type` / `twitter:card` を出す
- 画像は**その旅行の最初の写真**。配信元の `/share/<token>/media/<id>` は Access を通さないので、
  プレビューを作る側から取れる。写真が無い旅行は画像なし（`twitter:card` は `summary`）
- 本番の写真は中央値 1.49MB・最大 3.18MB（5MB 超えは 0 枚）なので、プレビュー用の縮小は作らず
  元の画像をそのまま使う。これより大きい写真が増えたら縮小の口を足す
- `generateMetadata` はページ本体とは別の軽い読み出し（`readShareMeta`）を使う。
  `readSharedTrip` は記録点を全部読むので、同じ処理を 1 リクエストで 2 回走らせない
